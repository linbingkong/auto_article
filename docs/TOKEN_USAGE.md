# Token 用量与成本看板

管理员侧边栏“Token 成本”用于统计文章生成过程中的 LLM 用量。系统按每次成功收到的模型响应记录一行，覆盖：大纲、每个章节、全文润色、事实修订、事实审计/重试和候选标题。

## 指标口径

- 输入 Token：服务商 `usage.prompt_tokens` / `input_tokens`
- 输出 Token：服务商 `usage.completion_tokens` / `output_tokens`
- 缓存与推理 Token：读取服务商 usage details（若提供）
- 服务商不返回 usage 时：按输入/输出文本长度近似计算，并标记“估算”
- 截断后重新生成等已返回响应会逐次记录，因为这些调用可能已产生账单
- 网络握手失败且没有模型响应时不计 Token

## 成本设置

配置中心“系统默认大模型”填写输入、输出单价，单位均为“元/百万 Token”。每次调用保存当时的单价快照：

`估算成本（元） = 输入 Token × 输入单价 / 1,000,000 + 输出 Token × 输出单价 / 1,000,000`

缓存折扣、阶梯价、免费额度和服务商账单调整不在公式内，因此看板只用于成本评估，不替代正式账单。

## 写作 Token 优化口径

完整证据仍保存在文章目录的 `evidence.txt`，写作时由 `EvidenceViews` 构造保留来源编号和 URL 的紧凑视图：

- 大纲：最多 14,000 字符，覆盖全部来源
- 每个章节：按主题和章节相关度选择最多 4 个来源、8,500 字符
- 全文润色：最多 5,000 字符，只提供事实边界和来源提示
- 事实修订：最多 22,000 字符，结合全部章节标题覆盖所有来源
- 事实审计：最多 14,000 字符
- 标题：最多 4,000 字符

导航链接等网页噪声会被剔除，带数字、日期、发布、公告、报告和回应的事实句优先保留。所有普通写作阶段显式关闭模型思考；输出预算分别收紧到大纲 1,024、章节 3,072、润色/事实修订 4,096、审计 3,072、标题 1,024 Token。服务商返回 `finish_reason=length` 时，LLM 客户端仍会自动增加预算重试，避免文章因硬截断丢失。

基于优化前已有的 15 篇文章测算，重复证据输入字符总量平均从 187,787 降至 61,320，整体下降约 67.3%；高证据量文章通常下降 70% 以上。实际 Token 和成本以管理看板中的服务商 usage 为准。

## MySQL 上线

SQLite 会自动创建 `llm_token_usage` 表。MySQL 运行时不执行 DDL，上线新版本前使用管理员账号执行：

```bash
mysql -uroot -p < database/add_token_usage_mysql.sql
```

如果应用账号不是 `wechat_agent_app@localhost`，请把迁移脚本末尾 GRANT 的 host 改成实际来源。

历史文章无法从文本反推出准确 Token，因此只统计功能上线后的模型调用。
